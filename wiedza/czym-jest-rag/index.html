KNOWLEDGE // RAG

Czym jest RAG i baza wiedzy AI?

RAG, czyli Retrieval Augmented Generation, łączy wyszukiwanie informacji w źródłach z generowaniem odpowiedzi przez model. Jakość zależy od całego pipeline'u, nie tylko od samego LLM.

RAGRETRIEVALSOURCES FIRST
Odpowiedź w skrócie

System RAG najpierw wyszukuje fragmenty wiedzy pasujące do zapytania, następnie przekazuje je modelowi jako kontekst. Jeżeli retrieval zwróci zły materiał, dobry model nadal może udzielić złej odpowiedzi.

Retrieval i generację mierzy się osobno

Najpierw należy sprawdzić, czy system odnalazł właściwy fragment. Dopiero później ocenia się, czy model poprawnie wykorzystał kontekst. Ocena tylko końcowej, dobrze brzmiącej odpowiedzi może ukryć problem w wyszukiwaniu.

Kiedy RAG ma sens

  • Wiedza zmienia się częściej niż sam model.
  • Informacje znajdują się w dokumentach lub bazach organizacji.
  • Potrzebny jest ślad źródła albo możliwość weryfikacji odpowiedzi.
  • Zakres wiedzy można ograniczyć do zatwierdzonych źródeł.

Kiedy RAG nie wystarczy

RAG nie zastępuje deterministycznej logiki biznesowej. Jeżeli wynik musi być jednoznaczny — np. obliczenie, walidacja limitu, zmiana statusu albo operacja transakcyjna — odpowiedzialność powinna pozostać w kodzie, regułach lub systemie źródłowym. Model może pomóc zinterpretować wejście, ale nie powinien przejmować roli systemu prawdy.

Typowe źródła błędów

Zły podział dokumentówZbyt duże fragmenty rozmywają kontekst, zbyt małe mogą tracić znaczenie.
Brak metadanychBez filtrów trudno respektować wersje, typy dokumentów i uprawnienia.
Słaby retrievalGeneracja nie naprawi kontekstu, którego system nie odnalazł.
Brak testów regresjiZmiana źródeł, indeksu lub modelu może zmienić zachowanie całego systemu.
Standard publikacji Tervyxa

Architektura, rekomendacja i wynik benchmarku to trzy różne rzeczy. Nie przedstawiamy opisu RAG jako dowodu osiągniętej jakości bez publicznego zestawu testowego, metody i wyniku.

Chcesz ocenić własne źródła wiedzy?
